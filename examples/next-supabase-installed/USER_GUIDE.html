Standard workflows

New feature

  1. Planner — paste the prompt on ticket 03.
  2. App engineer — Implement the plan. Smoke the changed route in the browser before you hand off.
  3. Security if data, auth, or secrets changed.
  4. Design if the UI changed — Act as design. Name the mode (setup, build, review, or detect). Review the running UI from screenshots first. Desktop and mobile. Reject generic AI-looking layout. If DESIGN.md is missing, run setup first.
  5. QA — paste the good prompt below.

Done when QA attaches both frames plus a verdict.

Auth / RLS

Planner → App engineer → Security → QA. QA must open login, logout, and denied in the browser. Screenshots still required when the finding is user-visible.

New repo design setup

After init, before the first product CSS, paste to Design:

Act as design. This is a new repo. Scan the architecture, then ask me about the product, audience, and first-screen job. Recommend principles and a token recipe. Write DESIGN.md and STYLE_GUIDE.md with me before any CSS.

Design scans the stack, asks a compact intake, recommends principles, then writes a short product DESIGN.md and frontend STYLE_GUIDE.md rules. It does not paste this kit’s charcoal desk onto the app. Screenshots wait until there is a screen to capture.

UI polish

Design + frontend-design + browser-qa. Name setup, build, review, or detect. Desktop and mobile once a screen exists. One happy-path shot is a fail.

Copy pass

Copy reviews the rendered words in screenshots, not strings in TSX. Run product-copy, then deslop last.

Do not review code alone. Open the app, capture desktop and mobile screenshots, read the images, then give accept / accept-with-nits / reject.
  1. Start or find the app (next dev or preview).
  2. Open the changed route with the real auth, role, and data.
  3. Capture desktop (~1280) and mobile (~390) into qa-evidence/<yyyy-mm-dd>-<slug>/.
  4. Read the images. List blockers from what is on screen.
  5. Run applicable tests. toBeVisible is not a screenshot.
  6. Write notes.md with route, viewports, auth state, verdict.

Adding more, updating, unblocking

npx agent-kit add agent lead-architect
npx agent-kit add skill debug
npx agent-kit update

Optional agents: lead-architect, docs, deploy, research. Optional skills: ui-polish, docs, upgrade, debug. Do not add them unless that specialist has a repeating job.

update refreshes pristine files. Local edits win or land in .agent-kit/conflicts/. It never deletes your old docs.
